# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

#### Данные
#### Интерфейс IProduct
Содержит поля для данных о продукте

Поля интерфейса: 
    `id: string` - идентификатор продукта
    `description: string` - дополнительное описание продукта
    `image: string` - изображение продукта
    `title: string` - наименование продукта
    `category: string` - категория продукта
    `price: number | null` - цена продукта

#### Интерфейс IBuyer 
Содержит поля для данных о покупателе

Поля интерфейса:
    `payment: TPayment | null` - способ оплаты
    `email: string` - электронная почта покупателя
    `phone: string` - телефон покупателя
    `address: string`- адрес покупателя

#### TPayment
Содержит варианты оплаты "cash" | "card";

### Модели данных
Отвечают за хранение и работу с данными.

#### Класс Catalog
Класс для взаимодействия с каталогом товаров

Конструктор класса принимает параметр:
`events: IEvents` - экземпляр брокера событий для генерации событий при изменении данных каталога

Поля класса: 
`products: Map<string, IProduct>` - словарь товаров каталога
`openedProduct: IProduct | null` - выбранный продукт
`events: IEvents` - экземпляр брокера событий

Методы класса:
`setItems(items: IProduct[]): void` - Заполнения каталога, принимает на вход массив IProduct
`getItems(): IProduct[]` - Получения массива товаров каталога
`getProductById(id: string): IProduct | undefined` - Получение продукта из каталога по идентификатору
`getSelectedProduct(): IProduct | null` - Получение выбранного продукта
`setSelectedProduct(id: string): void` - Установить выбранный продукт

#### Класс Basket
Класс для взаимодействия с корзиной покупателя

Конструктор класса принимает параметр:
`events: IEvents` - экземпляр брокера событий для генерации событий при изменении данных корзины

Поля класса: 
`_items: Map<string, IProduct>` - Словарь для хранения товаров в корзине, где ключ поле id продукта
`_events: IEvents` - экземпляр брокера событий
Методы класса:
`getItems(): IProduct[]` - Получение массива товаров, которые находятся в корзине
`add(item: IProduct): void` - Добавление товара, полученного в параметре, в словарь корзины
`remove(item: IProduct): void` - Удаление товара, полученного в параметре, из массива корзины
`clear(): void` - Очистка корзины
`getTotalPrice(): number` - Получение стоимости всех товаров в корзине
`getCount(): number` - Получение количества товаров в корзине
`hasProduct(id: string): boolean` - Проверка наличия товара в корзине по его id

#### Класс Buyer
Класс реализующий интерфейс IBuyer для хранения и валидации данных о покупателе

Конструктор класса принимает параметр:
`events: IEvents` - экземпляр брокера событий для генерации событий при изменении данных покупателя

Поля класса: 
`_payment: TPayment | null` - способ оплаты покупателя
`_email: string` - электронная почта покупателя
`_phone: string` - телефонный номер покупателя
`_address: string` - адрес покупателя
`_events: IEvents` - экземпляр брокера событий

Методы класса:
`get payment(): TPayment | null` - получение способа оплаты покупателя
`set payment(value: TPayment)` - установка способа оплаты покупателя 
`get email(): string` - получение электронной почты покупателя
`set email(value: string)` - установка электронной почты покупателя 
`get phone(): string` - получение телефонного номера покупателя
`set phone(value: string)` - установка телефонного номера покупателя
`get address(): string` - получение адреса покупателя
`set address(value: string)` - установка адреса покупателя 
`clear(): void` - очистка данных покупателя 
`validate(): BuyerErrors` - валидация данных о покупателе 

#### Тип BuyerErrors = Partial<Record<keyof IBuyer, string>>;
Описывание ошибки валидации информации о покупателе

Поля типа: 
`payment?: string;` - ошибка валидации способа оплаты
`email?: string;` - ошибка валидации электронной почты
`phone?: string;` - ошибка валидации телефонного номера
`address?: string;` - ошибка валидации адреса


### Слой коммуникации

#### Класс BackendApi
Класс для взаимодействия с сервером по Api

Конструктор класса принимает в качестве параметра объект реализующий интерфейс IApi

Поля класса:
`_api: IApi` - экземпляр объекта класса, реализующего интерфейс IApi;

Методы класса:
`getProducts(): Promise<ProductList>`- Метод отправки GET запроса на сервер для получения данных о списке продуктов
`createOrder(order: Order): Promise<OrderSuccess>` - метод для отправки POST запроса на сервер для создания заказа

#### Тип ProductList
Описывает модель ответ с сервере при получении списка продуктов

Поля типа: 
`total: number;` - общее количество товаров, которые есть в каталоге
`items: IProduct[]` - массив товаров

#### Интерфейс IOrder
Описывает модель для создания заказа при отправке запроса на сервер. Расширяет интерфейс IBuyer.

Поля типа: 
`payment: TPayment | null;` - способ оплаты покупателя
`email: string;` - электронная почта покупателя
`phone: string;` - телефон покупателя
`address: string;` - адрес покупателя
`total: number;` - общая стоимость товаров в заказе
`items: string[]` - массив идентификаторов товаров в заказе

#### Тип OrderSuccess
Описывает ответ с сервера при успешно созданном заказе

Поля типа:
`id: string;` - идентификатор успешно созданного заказа
`total: number;` - сумма заказа


### Слой представления

#### Класс Component
Дженерик абстрактный класс, который отвечает за рендер компонента

Конструктор класса примает параметр:
`protected readonly container: HTMLElement`- представляет собой элемент, который является контейнером для разметки компонента

Методы класса: 

`protected setImage(element: HTMLImageElement, src: string, alt?: string)` - метод для установки изображения с альтернативным текстом

`render(data?: Partial<T>): HTMLElement` - метод для рендера компонента в DOM элемент

#### Класс Basket
Класс отвечает за отображение корзины покупателя, наследуется от класса Component<IBasket>. Управляет списком товаров в корзине, отображением общей стоимости и кнопкой оформления заказа.

Конструктор класса принимает в качестве параметров:
`basket: HTMLElement` - корневой DOM-элемент контейнера корзины
`actions?: IBasketActions` - объект с обработчиками событий корзины

Поля класса:
`basketList: HTMLUListElement` - список товаров в корзине (элемент `<ul>`)
`orderButton: HTMLButtonElement` - кнопка оформления заказа
`priceElement: HTMLElement` - элемент отображения общей стоимости заказа

Методы класса:
`set basketItems(value: HTMLElement[])` - устанавливает список товаров в корзине. Если список пуст, кнопка оформления заказа блокируется. Принимает массив DOM-элементов карточек товаров.
`set price(value: number)` - устанавливает отображение общей стоимости заказа. Если значение не определено, отображается 0. Принимает общую стоимость товаров в синапсах.

#### Интерфейс IBasket
Определяет структуру данных, которые могут быть переданы в метод render для отображения в компоненте Basket.

Поля интерфейса:
`basketItems: HTMLElement[]` - массив DOM-элементов товаров в корзине
`price: number` - общая стоимость товаров в корзине

#### Интерфейс IBasketActions
Содержит callback-функции для обработки пользовательских действий в корзине.

Поля интерфейса:
`onOrderClick(): void` - обработчик нажатия на кнопку оформления заказа

#### Класс Card
Абстрактный базовый класс для карточек товаров. Наследуется от `Component<T>` и предоставляет базовую функциональность для отображения названия и цены товара. Является абстрактным классом и должен переопределяться в конкретных реализациях карточек (например, `CardCatalog`, `CardBasket`, `CardPreview`).

Конструктор класса:
`constructor(card: HTMLElement)` - создаёт экземпляр карточки товара. Принимает корневой DOM-элемент контейнера карточки.

Поля класса:
`titleElement: HTMLElement` - элемент отображения названия товара
`priceElement: HTMLElement` - элемент отображения цены товара

Методы класса:
`set title(value: string)` - устанавливает отображение названия товара. Принимает название товара для отображения.
`set price(value: number | null)` - устанавливает отображение цены товара. Если значение null или undefined, отображается 0. Принимает цену товара в синапсах.

#### Тип CardData
Тип данных карточки товара. Определяет минимальный набор полей для отображения карточки (название и цена).

Поля типа:
`title: string` - название товара
`price: number` - цена товара

#### Интерфейс ICardActions
Содержит callback-функции для обработки пользовательских действий с карточкой.

Поля интерфейса:
`onClick(event: Event): void` - обработчик клика по карточке

#### Класс CardBasket
Класс карточки товара в корзине покупателя. Наследуется от абстрактного класса `Card<CardBasketData>` и предоставляет функциональность для отображения позиции товара в корзине и кнопки удаления товара.

Конструктор класса:
`constructor(cardBasket: HTMLLIElement, actions?: ICardActions)` - создаёт экземпляр карточки товара в корзине. Принимает корневой DOM-элемент LI и опционально обработчик клика по кнопке удаления.

Поля класса:
`deleteButton: HTMLButtonElement` - кнопка удаления товара из корзины
`indexElement: HTMLElement` - элемент отображения номера позиции товара в корзине

Методы класса:
`set index(value: number)` - устанавливает отображение номера позиции товара в корзине. Принимает номер позиции товара (начиная с 1).

#### Тип CardBasketData
Тип данных карточки товара в корзине. Расширяет базовый тип `CardData` и добавляет поле номера позиции.

Поля типа:
`title: string` - название товара
`price: number` - цена товара
`index: number` - номер позиции товара в корзине

#### Класс CardCatalog
Класс карточки товара в каталоге. Наследуется от абстрактного класса `Card<CardCatalogData>` и предоставляет функциональность для отображения изображения, категории и названия товара.

Конструктор класса:
`constructor(cardCatalog: HTMLElement, actions?: ICardActions)` - создаёт экземпляр карточки товара в каталоге. Принимает корневой DOM-элемент контейнера карточки и опционально обработчик клика.

Поля класса:
`imageElement: HTMLImageElement` - элемент отображения изображения товара
`categoryElement: HTMLElement` - элемент отображения категории товара

Методы класса:
`set category(value: string)` - устанавливает отображение категории товара. Также добавляет соответствующий CSS-класс для стилизации категории. Принимает название категории товара.
`set image(value: string)` - устанавливает отображение изображения товара. Использует утилитарный метод setImage для установки источника и альтернативного текста. Принимает URL изображения товара.

#### Тип CardCatalogData
Тип данных карточки товара в каталоге. Расширяет базовый тип `CardData` и добавляет поля категории и изображения.

Поля типа:
`title: string` - название товара
`price: number` - цена товара
`category: string` - категория товара
`image: string` - URL изображения товара

#### Тип ProductBuyStateKey
Тип ключа состояния покупки товара. Описывает возможные состояния кнопки покупки: доступна, недоступна, добавлена.

Поля типа:
`buy` - товар доступен для покупки
`notAvailable` - товар недоступен для покупки
`delete` - товар добавлен в корзину (доступно удаление)

#### Класс CardPreview
Класс превью карточки товара (для просмотра деталей). Наследуется от абстрактного класса `Card<CardPreviewData>` и предоставляет функциональность для отображения изображения, категории, описания и кнопки покупки.

Конструктор класса:
`constructor(cardPreview: HTMLElement, actions?: ICardActions)` - создаёт экземпляр превью карточки товара. Принимает корневой DOM-элемент контейнера карточки и опционально обработчик клика по кнопке покупки.

Поля класса:
`imageElement: HTMLImageElement` - элемент отображения изображения товара
`categoryElement: HTMLElement` - элемент отображения категории товара
`descriptionElement: HTMLElement` - элемент отображения описания товара
`cardButton: HTMLButtonElement` - кнопка добавления товара в корзину

Методы класса:
`set category(value: string)` - устанавливает отображение категории товара. Также добавляет соответствующий CSS-класс для стилизации категории. Принимает название категории товара.
`set description(value: string)` - устанавливает отображение описания товара. Принимает описание товара.
`set image(value: string)` - устанавливает отображение изображения товара. Использует утилитарный метод setImage для установки источника и альтернативного текста. Принимает URL изображения товара.

### Презентер
Код презентера реализован в файле `src/main.ts` и отвечает за связывание моделей данных и компонентов представления, обработку событий пользователя и управление потоком приложения. Презентер использует событийно-ориентированный подход через класс `EventEmitter`.

#### Инициализация компонентов

При запуске приложения создаются экземпляры всех основных компонентов:
- **Модели**: `Catalog`, `Buyer`, `Basket` - отвечают за хранение и управление данными
- **Виды (Views)**: `Header`, `Gallery`, `Modal`, `Basket`, `OrderForm`, `ContactsForm`, `OrderSuccess` - отвечают за отображение
- **API**: `BackendApi` с базовым классом `Api` - для коммуникации с сервером

#### Обработка данных каталога

Функция `onCatalogChange()` вызывается при изменении данных в каталоге:
- Получает список товаров из модели `Catalog`
- Для каждого товара создает экземпляр `CardCatalog` с обработчиком клика
- При клике на карточку товара генерируется событие `card-catalog:select`
- Рендерит все карточки в компонент `Gallery`

#### Выбор и просмотр товара

Функция `onChangeSelectedProduct()` обрабатывает событие смены выбранного товара:
- Получает выбранный товар из `Catalog`
- Определяет состояние покупки (`buy`, `delete`, `notAvailable`) в зависимости от наличия товара в корзине и его цены
- Создает экземпляр `CardPreview` с данными товара и состоянием
- Отображает превью товара в модальном окне через `Modal`

### Просмотр корзины

Функция `onHeaderViewBasketClick` обрабатывает событие клика по кнопке корзины:
- делает ререндер корзины
- делает видимым модальное окно
- перерисовывает модальное окно

#### Управление корзиной

Функция `onBasketChange()` вызывается при изменении корзины:
- Перерисовывает корзину 
- Перерисовывает шапку

#### Обработка кликов по карточкам

Функция `onCardPreviewClick()` обрабатывает событие клика по кнопке покупки/удаления в превью товара:
- Если товар уже в корзине - удаляет его из корзины
- Если товар еще не в корзине - добавляет его в корзину
- Закрывает модальное окно

Функция `onCardBasketViewDelete()` обрабатывает событие удаление товара из корзины

#### Оформление заказа

Функция `onBasketViewOrderClick()` вызывается при нажатии на кнопку оформления заказа:
- Валидирует данные покупателя через `buyer.validate()`
- Рендерит форму заказа (`OrderForm`) с текущими данными покупателя и ошибками валидации в модальное окно

Функция `onOrderFormPaymentClick()` обрабатывает событие выбора способа оплаты:
- Устанавливает способ оплаты (`payment`) в модели `Buyer` на основе нажатой кнопки

Функция `onOrderFormAddressChange()` обрабатывает изменение поля адреса:
- Обновляет адрес в модели `Buyer`

Функция `onAddressOrPaymentChange()` вызывается при изменении адреса или способа оплаты:
- Валидирует данные покупателя через `buyer.validate()`
- Отображает ошибки валидации в форме заказа

Функция `onOrderFormNextClick()` обрабатывает событие клика по кнопке далее в форме заказа:
- Валидирует контактные данные покупателя через `buyer.validate()`
- Рендерит форму контактов (`ContactsForm`) с текущими данными и ошибками валидации в модальное окно

Функция `onEmailOrPhoneChange()` обрабатывает изменение email или телефона покупателя:
- Обновляет соответствующие поля в модели `Buyer`
- Вызывает валидацию контактов

Функция `onContactsFormPayClick()` обрабатывает событие клика по кнопке оплатить:
- Отправляет POST-запрос на сервер через `backendApi.createOrder()` с данными заказа (адрес, способ оплаты, email, телефон, общая сумма, список ID товаров)
- При успешном ответе рендерит сообщение об успешном заказе (`OrderSuccess`) с общей суммой из ответа сервера
- Очищает корзину (`basket.clear()`) и данные покупателя (`buyer.clear()`)
- При ошибке выводит сообщение в консоль

Функция `onContactsFormInputChange()` обрабатывает событие ввода email и телефона:
- Определяет имя измененного поля (атрибут `name` элемента `input`)
- Обновляет соответствующее поле в модели `Buyer` (`email` или `phone`)
- Обновление полей модели `Buyer` генерирует события `buyer:email-change` или `buyer:phone-change`, которые запускают валидацию через `onEmailOrPhoneChange()`

#### Получение данных с сервера

При загрузке приложения выполняется GET-запрос через `BackendApi.getProducts()`:
- Получает список товаров с сервера
- Добавляет базовый URL CDN к изображениям
- Заполняет каталог через `catalog.setItems()`
- При ошибке выводит сообщение в консоль

#### Подписка на события

В конце файла подключаются обработчики событий к `EventEmitter`:
- `catalog:change` - обновление каталога
- `card-basket-view:delete` - удаление товара из корзины
- `card-preview:click` - клик по кнопке покупки/удаления в превью товара
- `card-catalog:select` - выбор товара из каталога
- `catalog:change-selected-product` - изменение выбранного товара
- `basket:change` - изменение корзины
- `basket-view:order-click` - клик по кнопке оформления заказа в корзине
- `header-view:basket-click` - клик по кнопке корзины в шапке сайта
- `order-form:payment-click` - выбор способа оплаты
- `buyer:address-change` - изменение адреса покупателя (генерируется моделью Buyer)
- `buyer:payment-change` - изменение способа оплаты покупателя (генерируется моделью Buyer)
- `buyer:email-change` - изменение электронной почты покупателя (генерируется моделью Buyer)
- `buyer:phone-change` - изменение телефона покупателя (генерируется моделью Buyer)
- `order-form:address-change` - изменение в поле ввода адреса в форме заказа
- `order-form:next-click` - клик по кнопке "далее" в форме заказа
- `contacts-form:pay-click` - клик по кнопке "оплатить" в форме ввода контактов
- `contacts-form:email-change` - изменение в поле ввода email в форме контактов
- `contacts-form:phone-change` - изменение в поле ввода телефона в форме контактов
- `order-success-view:click` - клик по кнопке закрытия сообщения об успешном заказе
- `modal-view:close-click` - клик по кнопке закрытия модального окна

Таким образом, презентер обеспечивает полную связность компонентов и управление логикой приложения согласно архитектуре MVP.
